# Serato web library

Local browser for the Serato DJ Pro library. `server.py` uses the Python standard library. `desktop.py` opens that page in a native window and shuts the server down when the window closes. Optional sharing uses `sentry-sdk` and `posthog`, and stays off without a key and without consent. Python has no linter. The page uses ESLint. Tests use `unittest` and Vitest.

## Run

```bash
python3 server.py
```

Serves `http://127.0.0.1:8765`. A missing library still serves the page so setup can explain the next step. On macOS the usual library file is `~/Library/Application Support/Serato/Library/master.sqlite`. On Windows that file is `%LOCALAPPDATA%\Serato\Library\master.sqlite`. Stop the server with Ctrl-C.

The desktop app uses a local virtualenv, because Homebrew Python will not take a system-wide install:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python desktop.py
```

It binds `127.0.0.1` on a free port and opens a window titled crateCraft. Close the window to quit. A second launch focuses that window. On Windows, use `.venv\Scripts\python` in place of `.venv/bin/python`. On macOS, also install `requirements-macos.txt` so WKWebView can load. On Linux, install WebKitGTK (GTK 3 and WebKit2) or Qt WebKit. `.venv/` stays untracked. `CRATECRAFT_NO_WINDOW=1` or `--no-window` skips the window.

## Tests

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -t . -v
```

The suite imports `sentry-sdk` and `posthog`. It builds a temporary database. It does not open the live Serato library. Settings and logs for the run stay in a temporary directory.

The page tests, including the setup wizard, need Node 22 or newer:

```bash
npm ci
npm test
npm run typecheck
npm run build
npm run storybook
```

`npm run storybook` serves isolated React components at `http://127.0.0.1:6006`. Vite is the Storybook builder. The page still bundles with esbuild. Stories live in `src/stories/`, mirrored as `*.stories.tsx` under `components/`, `pages/`, or `containers/`. Context islands map Controls args through `src/lib/storybook/args.ts` into fixture providers. They do not mount the live `app/providers.tsx` stores. A push to `main` that changes those stories, `.storybook/`, or the page CSS publishes them at `https://mookiejones.github.io/crateCraft/storybook/`. `@storybook/addon-mcp` exposes MCP at `http://127.0.0.1:6006/mcp` while that process is running. `.grok/config.toml` registers it as `storybook`. When editing a component that has a story, use those MCP tools for docs and props.

The commands to paste into a pull request are the full list under [After a change](#after-a-change).

## Layout

The page uses a 200px navigation drawer and a 56px mini rail. Mini is forced at viewport widths of 980px or less. `layout.drawer_open` remembers the last toggle. The Crates room shares tree, list, and detail so Title / Artist / BPM stay readable; a saved list width cannot hide the tree or the detail. Search sits above crate actions. New, Rename, and Delete stay on one row; extras sit under More. The Data Grid owns horizontal scrolling and visible keyboard focus. MUI shares the page font and existing colorways.

- `server.py` is a `ThreadingHTTPServer` bound to `127.0.0.1:8765` when you run it directly. The desktop app asks for a free port instead. GET routes are `/api/health`, `/api/version`, `/api/help`, `/api/drive-check`, `/api/library`, `/api/status`, `/api/track`, `/api/audio`, `/api/waveform`, `/api/waveform/overview`, `/api/history`, `/api/history-stats`, `/api/history-stats.csv`, `/api/duplicates`, `/api/related`, `/api/library-roots`, `/api/files`, `/api/gig-check`, `/api/relink`, `/api/file-scan`, `/api/library-health`, `/api/album-art`, `/api/bitrate-check`, `/api/tempo-drift`, `/api/crate-compare`, `/api/tag-clusters`, `/api/lost-tags`, `/api/export.m3u`, `/api/export.rekordbox.xml`, `/api/settings`, `/api/setup`, `/api/logs`, `/api/legacy-library`, `/api/snapshots`, `/api/operations`, and `/api/update`. POST routes are `/api/shutdown`, `/api/focus`, `/api/help`, `/api/track`, `/api/crate`, `/api/import.m3u`, `/api/smart-preset`, `/api/crate-tree`, `/api/folder-sync`, `/api/history-stats`, `/api/reveal`, `/api/related`, `/api/duplicates/merge`, `/api/replace-in-crates`, `/api/files`, `/api/settings`, `/api/setup`, `/api/logs/open`, `/api/snapshots`, `/api/tag-clusters`, `/api/album-art`, `/api/bitrate-check`, and `/api/update`. Any other path is a file under `static/`. A request whose Host or Origin is not localhost, 127.0.0.1, or [::1] is refused. A frozen build reads `static/` from the PyInstaller bundle. `/api/health`, `/api/version`, `/api/help`, `/api/drive-check`, and `/api/update` do not open the library. `/api/version` returns `version`, `commit`, and `source`. `/api/shutdown` answers only when the desktop process set a token. When the library file exists, `serve` starts a poll of the Serato files that snapshots after an outside change. A missing library file still serves the page. Setup can then open a folder that already contains a Serato library. That choice does not create or modify the database.
- `drive_check.py` reads a portable drive's `_Serato_` crates and reports tracks that are not on that drive, tracks that cannot be found, Smart Crates, and FAT32-unsafe names. `python3 drive_check.py DRIVE` prints the report. `GET /api/drive-check` returns the same JSON. It does not write to the drive. Organize files shows Check drive on a removable Serato root. **Check drive** under Gig shows the same report: the person picks a connected drive that has a `_Serato_` folder. An unmounted drive is named and is not treated as a missing file.
- `rekordbox.py` writes a Rekordbox `DJ_PLAYLISTS` file and a loss report. `python3 rekordbox.py -o rekordbox.xml` prints the report. **Export**, **Import**, and **Rekordbox** show on Crates. **Rekordbox** opens a dialog with **Memory cues**, **Hot loops**, and the key notation, shows the report, and downloads the XML after confirm. **Hot loops** starts off and is remembered with Memory cues and the key notation in `settings.json`. The help line reads Uses a free hot-cue pad. Subcrates become nested playlist folders. Hot cues, loops, and the beatgrid are read with the Markers2 and BeatGrid parsers in `tags.py`. MP3 cue times are shifted from the LAME/Xing header, not by one amount for every file. Device Library Plus and OneLibrary are not written.
- `gig_check.py` is a read-only pre-gig check. `python3 gig_check.py` prints a ready score and a Holding it back list. It opens the database with `mode=ro` and audio with `rb`. It reads saved snapshots through `snapshots.SnapshotStore(..., recover=False)` and compares each snapshot's database copy and saved frames with the library now. `gig_snapshots.py` holds that comparison. With no snapshots the report says `No snapshots yet`. `volumes.py` names the drive a stored path lives on and whether it is plugged in, so a track on an unplugged drive is unavailable, not missing. `GET /api/library` and `GET /api/track` use that same split: Serato's missing flag on an unplugged drive becomes `offline` (with `offline_drive`), not `missing`. The Missing view lists only connected-drive missing files. Relink does not match offline tracks. `relink.py` suggests where missing tracks went, read-only: same name and size, same name, or same size and type, plus whole-folder moves. `python3 relink.py ROOT...` prints the plan, and `GET /api/relink?space=` searches the present music roots. Optional `root=` is an extra folder after a drive swap. The Missing view reviews matches and `POST /api/files` with `action: relink` rewrites the stored paths through the journal; audio is not moved.
- `snapshots.py` stores content-addressed, hash-checked snapshots of the database, per-drive `_Serato_` crates (including `database V2`), and Serato frames inside audio files. Frame bytes are read and written by `snapshot_frames.py`. `Export Backups` and `Lexicon` are never read or restored, including a Windows name with a trailing dot, a trailing space, or an alternate data stream. Restore saves a snapshot first, writes a journal before the first replace, can be previewed without writing, and refuses while Serato DJ is running or while the Serato version is unknown or Protect Library is on or unread. Lucid beatgrid storage is not parsed. It then registers any restored `.crate` or `.scrate` the database has not heard of, through the same write guards as a crate edit and without a second snapshot while the restore journal is open, so Serato 4 and 5 do not delete those files on launch. Registration is skipped when the snapshot has no master database, when `master.sqlite` is missing, or when the database has no Serato Library space. In that last case the plan warns that Serato may remove those crate files, and the restore still finishes. A crate whose snapshot copy cannot be read is reported as skipped and is not registered. An unfinished restore is rolled back when the store opens. After the files are replaced, restore checks them again. When no crate was registered, the database files are compared by byte hash. When crates were registered, row counts are compared: the snapshot's rows plus exactly those crates. The read copies the database and its WAL and opens the copy read-only, so the live file, `-wal`, and `-shm` stay unchanged. Indexes, triggers, views, and `PRAGMA integrity_check` must match, and in the `serato` table only the revision may change. Skipped crate files are left out of the file check. A mismatch puts the pre-restore snapshot back. The restore journal is removed only after that rollback's hash check passes. A failed rollback stays in the operation log and is not reported as a success. `SnapshotReader` exposes `list_snapshots` and `load`. `serato_web.completeness.is_complete` is the shared check for a finished snapshot or backup. `restore` calls `verify_legacy_backup` when `backup_status` is `legacy, unverified`, before the pre-restore snapshot.
- `serato_logs.py` reads the newest session logs in `_Serato_/Logs` and does not write them. A `[Library]` line names `master.sqlite` or `database V2`. A backup suffix after that name is ignored. A Serato DJ version line, including `Product name: Serato DJ Pro, Version: 4.0.10 (4010213)` and `Version: 5.0.0 (5001251)`, names Serato 4 or Serato 5. `Surface Version: 4.1` is OpenGL, not Serato DJ. A missing or empty folder leaves the installed-app version in place. A log can only make the write gate stricter. An unknown installed version stays `serato_version_unknown` even if the log names Serato 4. A log that does not name a dotted version uses that same notice. The `[Library]` path comes only from the newest log. `parse_logs` caches by mtime. macOS path checks ignore case. Serato 5 writes when Protect Library is off. A relocated library does not read the real logs unless `CRATECRAFT_LOGS` is an absolute path. The AppBar chip shows the generation. Its tooltip is `tooltip.libraryGeneration`.
- `serato_probe.py` prints which Serato 3 and Serato 4/5 library paths exist, including each external drive's `_Serato_` folder. `python3 serato_probe.py` does not open or create `master.sqlite`, `root.sqlite`, or `database V2`. It cannot tell Serato 5 from Serato 4 by those files. Lucid beatgrid storage is reported as unconfirmed. `docs/serato-5-macos.md` is the path note.
- `legacy_library.py` reads an older library that has `_Serato_/database V2` and `.crate` files but no `master.sqlite`, read-only: browse, missing (an unmounted drive is offline, not missing), and duplicates. Setup describes it in plain words instead of not found. `GET /api/legacy-library` returns it. Every POST except settings, setup, logs, help, shutdown, focus, related, and reveal answers 409 while only that library is present.
- `smart_presets.py` evaluates DJ presets (harmonic neighbours of a key, BPM within a range, not played in N months), each optionally scoped to one crate and its subcrates, and saves the result as a normal crate whose name ends in `⟳` (part 1 of #26). `POST /api/smart-preset` previews read-only, creates, refreshes, or lists. Create and refresh go through `safe_write`. The preset is remembered in `preset-crates.json` beside `settings.json`, never in the Serato folder, with the crate's added time. A crate delete prunes stale records and refresh checks the added time, so a reused crate id is never refreshed. `GET /api/library` lists them as `presets`. In the page, **Preset** in the crate actions opens the dialog (`src/lib/crates/presets.ts`, pure helpers in `src/lib/crates/preset-view.ts`), **Refresh** shows on a preset crate, and the page calls `refresh_all` once on open, which writes only when a crate changed.
- `crate_trees.py` builds a crate tree: a parent crate with a `⟳` preset subcrate per BPM band (overlapping when the step is smaller than the width), per key in Camelot order, or per genre (spellings grouped, a minimum size and a cap), optionally limited to one crate (part 1 of #31). `POST /api/crate-tree` previews read-only or creates the whole tree in one `safe_write` session. Empty subcrates are not made. The subcrates refresh like any preset crate.
- `folder_sync.py` keeps a crate's tracks in step with a music folder (issue #210). `python3 folder_sync.py CRATE FOLDER` prints the preview. `--sync` writes. `POST /api/folder-sync` previews read-only or writes through `safe_write`. Default is recursive add-only of library tracks whose files sit under the folder. Optional subcrates map each subfolder to a child crate. Optional full removes members whose files are not in that crate's folder. Files that are not in the library are skipped and are not imported. A plan with nothing to change does not write. In the page, **Sync folder** in the crate actions opens the dialog (`src/lib/crates/folder-sync.ts`, pure helpers in `src/lib/crates/folder-sync-view.ts`).
- `crate_compare.py` compares two crates, read-only: tracks in both, only in A, and only in B, in crate order, optionally with subcrates. A smart crate is marked because its stored members can be stale. `GET /api/crate-compare` returns it. Saving a result as a crate is not built yet.
- `related.py` stores track links in `related.sqlite` beside `settings.json`, not in `master.sqlite`. `library.update_related_path` points those links at a new path after a file move. The schema is `docs/related-tracks.md`. `GET /api/related?path=` returns saved links and suggestions.
- `desktop.py` starts that server on a free port and opens a pywebview window titled crateCraft. The window has a native menu that calls the page, reading titles from bundled `locales/`. Music and Tools list the same destinations as the drawer, in the same words. The Mac Edit and View menus stay the shell defaults. `python3 server.py` has no menu. The window uses the system web view: WebView2 on Windows, WKWebView on macOS, and WebKitGTK or Qt WebKit on Linux. Chromium is not bundled. The spec bakes `packaging/app-icon.icns` into the macOS `.app` and `packaging/app-icon.ico` into the Windows `.exe`; Inno Setup uses that ICO as `SetupIconFile`. Source `desktop.py` passes the same default to `create_window` when the file is present. When the theme changes, and again when the window is shown, the running Dock icon on macOS or the window and taskbar icon on Windows switches to that colorway if App icon follows the theme is on, which is the default. The Finder icon and the Windows program icon stay that baked default. Other platforms leave the icon alone. `app_icons.py` draws the four placeholder icons from the circle in `packaging/menu-icon.png`, and draws the baked default from `static/img/icons/default.svg` without the word PLACEHOLDER. Closing the window POSTs `/api/shutdown` with the desktop token. A second launch POSTs `/api/focus` and the running process brings the window forward. `requirements.txt` pins pywebview, sentry-sdk, posthog, miniaudio, cffi, pycparser, and numpy, and pins pythonnet on Windows. `pyrightconfig.json` strict-checks `waveform.py` and `waveform_native.py`. `requirements-build.txt` repeats those pins and also pins PyInstaller. `requirements-macos.txt` pins the PyObjC frameworks WKWebView needs. `static_assets.py` lists the local files `static/index.html` references, and `crateCraft.spec` exits when one is missing or pywebview is missing. The spec builds a windowed app named crateCraft for the OS you build on. `CRATECRAFT_SMOKE` is an absolute marker path. The process writes the URL and a shutdown token there, serves `/api/health` without opening the library, a window, or telemetry, and exits when the harness posts that token. `CRATECRAFT_NO_WINDOW=1` or `--no-window` skips the window on a normal launch. The window size and position are stored in `settings.json`. A saved position is restored when a 100 by 40 pixel strip of the title bar is on a screen, including a monitor with a negative origin. Otherwise the window is centered on the primary screen. A crash leaves the lock free; the next launch deletes the leftover `instance.port`.
- `telemetry.py` sends anonymous counts and crash reports after consent, and only when a key is present. `app_config.py` stores the choice, a random install id, `wizard_complete`, the window frame, the track list width, `layout.drawer_open`, the page `language` (`en` or `es`; missing follows the OS), `colorway` (`serato-like`, `dark-club`, `light`, or `classic`; missing is Serato-like; saved `motown`, `deep-house`, or `daisy-age` load as Classic), and `icon_follows_theme` (missing is true; false keeps the usual icon). `library.json` beside `settings.json` remembers a library file chosen in setup when the usual one is missing. That path stays on this computer and is not a usage report. `setup_flow.py` describes the library in plain words for the first-run wizard. `app_log.py` writes a rotating log. `_build_config.py` is the empty key file that a release build overwrites. `_version.py` is the empty version file that the same build overwrites from the release tag. `version_info.py` resolves that file, `git describe`, or `0.0.0+dev` when git is missing. `app_config.APP_VERSION` and `__version__` are that string, and `GET /api/settings` returns it as `app_version`. The Windows spec writes a PyInstaller version file from the same identity. `update_check.py` asks GitHub's public releases API whether a newer release exists, at most once a day and only after the person turns it on; `updates.json` beside `settings.json` holds that choice and the cache. `PRIVACY.md` is the public note.

- `.github/workflows/` runs CI (the suite, a TypeScript check of `src/`, Vitest in jsdom, a freshness check of the committed `static/app.js` and `static/wizard.js` bundles, and a pip-audit of the requirements files), CodeQL, dependency review on pull requests, a prepare-release job on `main` that drafts the next version and notes into the **Next release** issue without tagging, a milestone-empty job that comments on that issue when a GitHub milestone has no open items (it does not tag or close the milestone), and a release workflow that builds the page bundle before PyInstaller and then builds unsigned macOS disk images and a Windows installer plus portable zip. Dependabot also updates the Node toolchain. A pull request that changes the packaging files or the page bundle (`static/app.js` or `static/app.css`) runs those builds and uploads the artifacts. Only a tag push publishes a GitHub Release. That is the only download. `docs/github.md` is the guide.
- `scripts/release_bundle.py` checks a PyInstaller tree, writes the macOS disk image or the Windows zip and installer, checks the Windows version resource with `assert-version`, and launches the unpacked app with `CRATECRAFT_SMOKE`. `scripts/write_version.py` writes `_version.py` before PyInstaller. The harness hits `/api/health` and shuts the app down. The publish job checks the files and `SHA256SUMS` and does not launch them. `scripts/release_sign.py` signs only when the Apple or Windows secrets are all set. When they are absent it skips and exits 0.
- `library.py` reads and writes `master.sqlite`. The live path is Application Support on macOS and `%LOCALAPPDATA%\Serato\Library` on Windows. `root.sqlite` beside the master file is updated when it is attached. Writes are refused while a live Serato process holds the lock. The first write in a process copies both databases and each present drive's `_Serato_` folder into `Library/Backups` when `begin_write` runs outside a `safe_write` session. An unplugged drive is listed and skipped. An unreadable subdirectory skips that drive, records `permission`, and does not block later writes. `Recording` and `DJ Sessions` are not copied. The copy is refused when the disk does not have room. Nothing is written on the external drive. `safe_write.py` stores the pre-write copy, `write-journal.json`, and `operations.jsonl` in the app data folder (`write-checks` beside `settings.json`). It checks a temporary copy of the database and any `-wal` file after the commit, and puts that copy back when the rows or hashes do not match. A library edit through that session does not add `Backups`, `snapshots`, a write journal, or `operations.jsonl` beside `master.sqlite`. Serato 5 uses that same verify-and-rollback path when Protect Library is off. `serato_web/completeness.py` is the shared check for a finished backup or snapshot directory (`is_complete`, `verify_legacy_backup`). Reveal uses Finder on macOS and File Explorer on Windows.
- `music_roots.py` finds the Files page roots: track folders in `master.sqlite` collapsed to their common music folder, plus each mounted drive with a `_Serato_` folder. `~/Music` and `~/Downloads` stay separate, and a root is not widened to home, `/`, `/Volumes`, or a drive root. The label is the folder or volume name, with `(parent)` added until it is unique. A folder on an unmounted drive stays in the list and is marked missing. macOS looks in `/Volumes`. Windows checks mounted drive letters. The list is cached until `invalidate()` or `refresh=1`. A change to `master.sqlite` or its WAL does not recompute it.
- `file_scan.py` finds damaged audio files, read-only: empty, unreadable, or not the format the extension says (a web page saved as `.mp3`), Serato's own corrupt flag, and with `depth=full` a decode that fails or comes out much shorter than the stored length. `python3 file_scan.py` prints the report. `GET /api/file-scan` returns it; a full check from the page needs a crate. **Damaged files** under Health shows the report. A "suspect files" crate is not built yet.
- `library_health.py` is a read-only one-page health report from the database and from audio files on disk: missing files, no BPM, no key, no beatgrid, no artwork, empty genre, tracks in no crate, unused files, and duplicate groups. `python3 library_health.py` prints the JSON. `GET /api/library-health?space=&crate=` returns it. **Overview** under Health shows the report. A crate keeps the crate list. Unused files and not-in-a-crate are empty when a crate is selected.
- `album_art.py` finds tracks with no artwork and embeds a Cover Art Archive image (#32). `python3 album_art.py --id N preview` prints the plan. `GET /api/album-art` lists the same no-artwork sample as library health. `POST /api/album-art` with `action: preview` looks up MusicBrainz and Cover Art Archive without writing; `action: embed` with `confirm` true writes JPEG or PNG through `safe_write` with Serato closed. Cover URLs are built from a MusicBrainz release id. `fetch_url` compares hostname, not a substring of the URL. GEOB frames stay. MP4 is refused. **Find art** on an Overview no-artwork row opens the dialog (`src/lib/health/album-art.ts`).
- `bitrate_check.py` flags fake 320s, read-only: it finds the lossy encoder's high-frequency cliff in a sample of each file's spectrum and reports a file whose stated bitrate is at least 1.5 times what that cliff shows, or a FLAC, WAV, or AIFF with a lossy cliff. `python3 bitrate_check.py` prints the report. `GET /api/bitrate-check` returns it for one crate. **Suspect quality** under Health shows the report. `POST /api/bitrate-check` with `action: preview` lists a crate of flagged tracks; `action: create` writes that crate through `safe_write` with Serato closed. A plan with nothing to change does not write.
- `tempo_drift.py` flags tracks whose tempo wanders or that look live, read-only: hop RMS envelope plus autocorrelation, folded into 70–140 so 60 vs 120 is not drift; a BeatGrid whose implied BPM already spreads is skipped; live is word-bounded; Serato's pending tempo-map mark is listed. `python3 tempo_drift.py` prints the report. `GET /api/tempo-drift` returns it for one crate. **Tempo drift** under Gig shows the report. A wrong constant BPM is not rewritten.
- `history_stats.py` summarises play history: the most played tracks and artists between two times, plays and sessions, and the tracks in a space not played for `idle_days` (365 by default). `python3 history_stats.py` prints JSON; `--csv` prints a spreadsheet. `GET /api/history-stats` returns it. `GET /api/history-stats.csv` downloads that spreadsheet. **Play stats** under Music shows the report. `POST /api/history-stats` with `preview` lists idle tracks; `create` makes a crate of them through `crate_action` (Serato must be quit).
- `tag_cleanup.py` groups spellings of one genre or artist ("Hip Hop", "Hip-Hop", "hiphop") with track counts and a suggested spelling. `GET /api/tag-clusters?space=&field=genre|artist` returns the groups. `POST /api/tag-clusters` with `action: preview` lists the rows a chosen stored spelling would rewrite; `action: apply` writes that spelling through `safe_write` with Serato closed. `clean_title` strips a leading track number, URLs, and `(Original Mix)`, moves feat. into remixer when remixer is empty, and title-cases a title that is all upper or all lower. `action: clean-preview` lists those rows; `action: clean-apply` writes them through `safe_write` with Serato closed. Audio files are not rewritten. A plan with nothing to change does not write. `apply` also stores the chosen spelling in `tag-spellings.json` beside `settings.json`, keyed by the library file and the `normalize` key, never in the Serato folder. `action: refresh-preview` lists rows that still use another spelling of a saved key; `action: refresh-apply` writes them through `safe_write` with Serato closed. **Tag spellings** under Health shows the groups. Genre, Artist, and Titles switch the field. Genre and Artist also post `refresh-preview` and show **Apply saved mappings** when rows would change. Titles skips that preview. Review posts a preview. Apply writes the chosen spelling, or the cleaned titles, through that same POST. Audio files are not rewritten. A multi-select field editor and writing tags into audio files are later changes.
- `files.py` renames, moves, replaces, relinks missing tracks, and trashes audio. `rename_from_tags` bulk-renames library files to `Artist - Title.ext` from the library row, then the file tags, and rewrites stored paths the same way as a single rename. It updates path columns in `master.sqlite` and the mirrored location database in one transaction, after a backup, and only while Serato is quit. Relink rewrites those paths and does not move the audio. A journal under `Library/Backups` puts the files back if the database write fails. A successful move also updates related-track paths.
- `tags.py` reads Serato markers from ID3 GEOB frames (`Markers2`, `BeatGrid`), from FLAC Vorbis comments (`SERATO_MARKERS_V2`, `SERATO_BEATGRID`), and from M4A/MP4 freeform atoms (`----:com.serato.dj:markersv2` and `beatgrid`). `read_text_tags` reads the file's own title and artist (ID3 `TIT2`/`TPE1`, Vorbis `TITLE`/`ARTIST`, MP4 `©nam`/`©ART`) without rewriting it, and `lost_tags.py` uses it to list tracks whose title or artist is blank in the database but set in the file, read-only; `GET /api/lost-tags?space=` returns that list. `read_serato_overview` reads the `Serato Overview` tag from those same containers, and from an Ogg Vorbis comment, without rewriting the file. Marker parsing still ignores that tag. It can copy GEOB frames onto a plain ID3v2.3 file or an MP3 that has no tag yet. `embed_front_cover` writes a JPEG or PNG front cover on an MP3 or FLAC that has none and keeps GEOB and FLAC Vorbis comments. FLAC, M4A, and other layouts are left unchanged by that copy. `snapshot_frames.py` is what puts a snapshot's exact Markers2, BeatGrid, and Autotags bytes back. A full ID3 rewrite from another program can still drop those frames.
- `waveform.py` builds a mono three-band waveform for `GET /api/waveform`. The id check is the same one `/api/audio` uses. Low is under 250 Hz, mid is 250 Hz to 4 kHz, and high is over 4 kHz, split with FFT overlap-save. Detail is 150 points per second and the overview is about 1000 points. A 60-minute stereo 44.1 kHz WAV takes 7.9 seconds. The body is little-endian `SWF1`. miniaudio decodes wav, aiff, flac, mp3, and ogg. m4a, aac, and alac are decoded with macOS AudioToolbox (`afconvert` writes a temporary WAV under the system temp directory) or Windows Media Foundation in memory. Linux uses `ffmpeg` only when it is already on `PATH`. ffmpeg is not bundled. The temp file is removed when decoding finishes or fails, and it is not written beside the audio file or inside the Serato folder. A file that cannot be decoded returns `waveform unavailable`, and playback is unchanged. The page shows that with `t("player.waveformUnavailable")`. The cache is `<config>/waveforms`, keyed by real path, size, mtime, and analyzer version. It is not written inside the Serato folder. `GET /api/waveform/overview` returns the file's Serato Overview without decoding. `GET /api/track` already returns cues, loops (color and locked), and the beatgrid; `position_seconds` is the stored float so beat times can be computed.

## After a change

1. Update `docs/architecture.md` when behavior, the API, the layout, or the run path changes.
2. Update `CLAUDE.md` and `AGENTS.md` together. They are copies of the same text. Update them when the run command or the layout summary changes.
3. Update `docs/github.md` when a workflow, a release check, or a GitHub setting changes.
4. Update `PRIVACY.md` and the README when sharing, local logs, or telemetry keys change.
5. A change a DJ can see also updates `docs/wiki/` and the user guide (`docs/index.md`, `docs/guide/`, `docs/quick-start.md`, `docs/first-install.md`). Use the `updating-user-docs` skill.
6. Tests. Every behavior change or bug fix ships with tests in the same PR: Python `unittest` under `tests/`, page code as Vitest `*.test.ts` in `src/tests/`. A bug fix needs a test that fails before the fix. Use only synthetic fixtures (`tests/fixtures/`), never a real `master.sqlite`, `root.sqlite`, or audio file.
7. Before opening a PR, run all checks locally and paste the results in the completion report:
   ```bash
   python3 -m pip install -r requirements.txt
   python3 -m unittest discover -s tests -t . -v
   npm ci
   npx tsc --noEmit
   npx tsc --noEmit -p e2e
   npx eslint src e2e
   npm test
   npx playwright install chromium
   npx playwright test -c e2e/playwright.config.ts
   npm run build
   ```
   Commit the rebuilt `static/app.js` and `static/wizard.js`.
8. Push to a branch and open a PR. Never push to `main`.
9. Write the [completion report](#completion-report) in the pull request body. When the work has an issue, post the same report as a final comment on that issue.

## Test bar

QA (Gatekeeper, account `mookiejones-qa`) blocks a PR whose tests do not meet this bar:

- Tests must fail if the logic is broken. QA may mutation-test; weak tests that pass anyway get blocked.
- Cover the edge cases that apply to the change: Windows and macOS paths, symlinks and unmounted drives, Serato 4 vs Serato 5 data, and an empty or missing library.
- Never write extra files inside the Serato folder.

## Completion report

Every agent (Claude, Cursor, and others) finishes each issue with a completion report. The report goes in the pull request body. When the work has an issue, the same report is the final comment on that issue. `CONTRIBUTING.md`, `.github/pull_request_template.md`, and [docs/github.md](docs/github.md) use this template.

Saying "done", without the issue link, the pull request link, the commit SHA, and the test output, does not count. Never claim work you did not push. The SHA is a commit on the remote branch, and each test line is a command you ran on that commit.

**What changed** is at most three bullets. **Proof** uses the exact commands in [After a change](#after-a-change). Each command that prints a pass count includes that count. Each other command includes pass or fail. Proof names the CI status of every check in [Merge rules](#merge-rules) and includes a screenshot when the change is visible in the page. A change with no page UI says there is no screenshot. **Next** says what is needed from Charles (@mookiejones) or QA (`mookiejones-qa`). Merge only when [Merge rules](#merge-rules) allow it.

- **Issue:** link
- **PR and commit:** link and SHA
- **What changed:** up to 3 bullets
- **Proof:** the exact test commands with their pass counts, CI status, and a screenshot for UI changes
- **Not done / risks:**
- **Next:** what is needed from Charles (@mookiejones) or QA (`mookiejones-qa`)
